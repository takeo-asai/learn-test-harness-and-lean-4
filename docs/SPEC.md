# kvjson 仕様

簡易 CSV/Key-Value テキストと JSON を相互変換する CLI。
テストハーネスはこの文書だけを根拠に書かれており、実装言語には依存しない。

## コマンドライン

| 呼び出し | 動作 |
| --- | --- |
| `kvjson to-json` | 標準入力の KV テキストを JSON に変換して標準出力へ |
| `kvjson from-json` | 標準入力の JSON を KV テキスト（正規形）に変換して標準出力へ |
| `kvjson --help` / `-h` | 使い方を標準出力へ、終了コード 0 |
| それ以外（引数なし・未知のサブコマンド・引数過多） | 使い方を標準エラーへ、終了コード 2 |

### 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 成功 |
| 1 | 入力が不正（変換できない） |
| 2 | 使い方の誤り |

入力が不正なとき（終了コード 1）は:

- 標準出力に**何も書かない**
- 標準エラーに 1 行以上のメッセージを書く
- クラッシュ（panic・シグナル終了など）してはならない

## KV テキスト形式

- 入力は UTF-8。不正な UTF-8 はエラー。
- 1 行 = 1 レコード。行区切りは `\n`。最後の `\n` は省略してよい。
  - 空の入力 `""` → レコード 0 件
  - 空行 → 空レコード `{}`（例: `"\n"` → `[{}]`）
- レコードは `,` 区切りのフィールドの並び。各フィールドは `key=value`。
- キーは空にできない。同じレコード内でキーが重複したらエラー。値は空でもよい。
- キーと値の中では次のエスケープを使う。それ以外の `\x` はエラー。

| エスケープ | 意味 |
| --- | --- |
| `\\` | `\` |
| `\,` | `,` |
| `\=` | `=` |
| `\n` | 改行 |

- エスケープされていない `,` `=` `\` がそのまま来たらエラーになる。具体的には:
  - `=` がないフィールド（例: `a`、`a=1,` の末尾の空フィールド）
  - 値の中に `=` がもう一つある（例: `a=1=2`）
  - 行末の `\`（例: `a=1\`）
- `\r` などそれ以外の文字は、すべてそのままの文字として扱う。

## JSON 形式

- `to-json` は「文字列→文字列のオブジェクト」の配列を出力する。末尾に改行を付ける。
  比較は JSON の値として行う（空白、キーの順序、`\u` エスケープの有無は問わない）。
- `from-json` の入力は「文字列→文字列のオブジェクト」の配列でなければならない。違えばエラー:
  - トップレベルが配列でない（`null` や `{}` を含む）
  - 要素がオブジェクトでない（`null` を含む）
  - 値が文字列でない
  - キーが空文字列
  - JSON として不正（末尾にゴミがある場合も含む）
- JSON オブジェクト内でキーが重複したときの動作は未定義（テストしない）。
- JSON 文字列中の対になっていないサロゲート（例: `"\ud800"`）の扱いは未定義（テストしない）。
  KV テキストは UTF-8 なので、これを表現できない。
  PBT の初回実行で見つかった仕様の穴。

## 正規形（`from-json` の出力）

- 1 レコードごとに 1 行を出力し、各行は必ず `\n` で終える（空レコードは空行になる）。
- フィールドはキーの UTF-8 バイト列の昇順に並べる。
- キーと値は上の 4 文字（`\` `,` `=` 改行）を**必ず**エスケープし、それ以外はエスケープしない。

## 満たすべき性質（ハーネスが検査する）

1. `to-json(from-json(J)) == J`（J は任意の妥当な JSON）
2. `from-json(J)` は正規形とバイト単位で一致する
3. 妥当な KV テキスト T について、`to-json(T)` は T の意味と一致する（フィールドの順序と末尾の改行は問わない）
4. 任意のバイト列について、受理するかどうかとその結果が、仕様どおりの参照モデルと一致する
5. どんな入力でも終了コードは 0 か 1 で、クラッシュしない
