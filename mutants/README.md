# mutants/: わざと入れたバグ（ミューテーションテスト用）

## 何をしているか

各 `.patch` は [cli/](../cli/) の Go コードに**小さなバグを 1 つだけ**入れる差分です。
バグを入れた版を**ミュータント**と呼びます。
コンテナのビルド時（[Dockerfile](../Dockerfile) の `mutants` ステージ）に、パッチを 1 個ずつ当てて別々の実行ファイルにします（`/opt/mutants/<名前>`）。
[harness/run_mutation.sh](../harness/run_mutation.sh) が、すべてのミュータントに例ベースと PBT の両方を当てて、結果を数えます。

- **Killed**: テストが失敗した。テストがそのバグを検出できた
- **Survived**: テストが通ってしまった。テストに穴がある（または等価ミュータント）

```bash
make mutation
```

## なぜ必要か

「テストが全部通る」だけでは、テストが何かを確かめている証拠になりません。
何も検査しないテストでも全部通ります。
ミューテーションテストは、**テストがバグを見つけられるか**を測ります。いわばテストのテストです。
Survived が出たら、そのバグを捕まえるテストを足すか、捕まえる必要がない理由を説明します。

今回の結果では、例ベースと PBT がそれぞれ別のバグを見逃しました（m14 と m05）。
両方を持つ理由が、数字で確認できます（詳しくは [harness/README.md](../harness/README.md)）。

## なぜ手書きのパッチなのか

Go には go-mutesting のような自動ミューテーションツールもあります。
ただ、自動で作ると、数百個のうち大半が意味のない変更や等価な変更になりがちです。
今回の目的は「どんな種類のバグを、どちらのテストが捕まえるか」を読むことです。
そこで、**仕様の各項目を破るバグ**を 1 個ずつ手で選びました。
パッチなので、何を変えたかが `cat` で読めます。

## 一覧

| ミュータント | 入れたバグ | 破る仕様 |
| --- | --- | --- |
| `m01_escape_misses_comma` | 出力で `,` をエスケープしない | 正規形: 4 文字は必ずエスケープ |
| `m02_unknown_escape_is_literal` | `\t` などの未知のエスケープを文字として通す | それ以外の `\x` はエラー |
| `m03_dangling_escape_accepted` | 行末の `\` を受理する | 行末の `\` はエラー |
| `m04_keys_reverse_sorted` | キーを降順に並べる | キーは昇順 |
| `m05_duplicate_key_last_wins` | キーの重複を通す（後勝ち） | キーの重複はエラー |
| `m06_empty_key_accepted` | 空のキーを受理する | キーは空にできない |
| `m07_exit_0_on_invalid_input` | 不正な入力でも終了コード 0 | 不正な入力は終了コード 1 |
| `m08_newline_escape_decodes_to_n` | `\n` を改行ではなく `n` にする | `\n` は改行 |
| `m09_panic_on_dangling_escape` | 行末の `\` で範囲外アクセス（panic） | クラッシュしてはならない |
| `m10_html_escape_in_json` | JSON 出力で `<` を `<` にする | （破らない。等価ミュータント） |
| `m11_trailing_newline_makes_record` | 末尾の `\n` で空レコードが 1 つ増える | 最後の `\n` は省略可で、レコードを増やさない |
| `m12_null_accepted_as_empty` | トップレベルの `null` を空配列として受理 | トップレベルは配列 |
| `m13_cr_stripped` | 行末の `\r` を削る | `\r` はそのままの文字 |
| `m14_escape_only_first_comma` | 2 個目以降の `,` をエスケープしない | 正規形: 4 文字は必ずエスケープ |
| `m15_utf8_check_skipped` | 不正な UTF-8 を通す | 不正な UTF-8 はエラー |

### 等価ミュータント（m10）

`"<"` と `"<"` は、JSON の値としてはまったく同じ文字列です。
仕様は JSON を値として比べると決めているので、m10 は仕様違反ではなく、どのテストも検出できません（検出すべきでもありません）。
ミューテーションスコアが 100% にならない理由として、意図的に入れてあります。

## パッチの足し方

1. `cli/` をコピーしてバグを入れ、`diff -u` で差分を取る（パスは `a/kv.go` `b/kv.go` の形）。
2. `mutants/mNN_説明.patch` として保存する。
3. `make mutation` を実行する。

```bash
cp -r cli /tmp/a && cp -r cli /tmp/b   # /tmp/b/kv.go を編集してから
```

```bash
(cd /tmp && diff -u a/kv.go b/kv.go) > mutants/m16_example.patch
```

`cli/` のコードを変えたら、パッチの前後の行が合わなくなることがあります。
その場合はビルドの `patch` で失敗するので、作り直してください。
