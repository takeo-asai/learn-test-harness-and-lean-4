# lean/: エスケープの規則を Lean 4 で証明する（おまけ）

## 結論: 何を証明しているか

**エスケープの規則そのものに穴がないこと**を証明しています。
**Go の実装が正しいことは証明していません。** 実装は、証明済みの関数との差分比較で確かめます。

## 証明の対象

仕様（[docs/SPEC.md](../docs/SPEC.md)）のエスケープの部分だけを、[KvEscape.lean](KvEscape.lean) に Lean の関数として書き直しています。

| 関数 | 動作 |
| --- | --- |
| `escape` | `\` `,` `=` 改行の 4 文字を `\\` `\,` `\=` `\n` にする。ほかの文字はそのまま |
| `unescape` | その逆。未知のエスケープ（`\t` など）、行末の `\`、エスケープされていない特殊文字があれば失敗（`none`）にする |

## 証明している 2 つの定理

### 1. `unescape_escape`: どんな文字列 `s` でも `unescape (escape s) = some s`

エスケープしてからデコードすると、**必ず**元の文字列に戻ります。
特殊文字がいくつ、どこに、どんな並びで入っていても成り立ちます。

### 2. `escape_injective`: `escape s = escape t` ならば `s = t`

異なる値が、同じテキストに化けることはありません。
たとえば値 `a,b` と、値 `a` の後ろに別のフィールドが続く形とが、出力上で区別できなくなることはない、という意味です。
定理 1 からすぐに導けます。

## テストとの違い

- テストは有限個の入力しか試しません。PBT の 200 例が通っても、201 例目で壊れないとは言えません。
- 証明は**すべての文字列について**成り立つことを、Lean が機械的に検査します。
  `lake build` が通ること自体が、証明が正しいことの確認です。間違っていればビルドが失敗します。
- 規則の設計を誤れば、証明は通りません。
  たとえば `,` をエスケープし忘れる規則（ミュータント m01 と同じ誤り）にしたとします。
  `unescape` はエスケープされていない `,` を拒否するので、元に戻らなくなり、定理 1 が成り立ちません。

## 証明していないこと

| 証明していないこと | どう補っているか |
| --- | --- |
| Go の実装が正しいこと | `diff.sh` で、証明済みの関数から作った実行ファイルと Go の CLI をサンプル入力（30 件）で比べる |
| 行やフィールドの分割、キーの重複、空キー | 例ベースのテストと PBT（[harness/](../harness/)） |
| JSON の読み書き、キーの並び順 | 同上 |
| `unescape` が、拒否すべき入力をちょうど拒否すること | 証明していない。定理 1 が言うのは「正しくエスケープされた入力は受理され、元に戻る」ことだけ |
| Lean のモデルが SPEC.md の文章と一致していること | 人が読んで確認するしかない |

保証の範囲は「仕様のうちエスケープの層は、往復すれば必ず元に戻り、衝突しない」までです。
Go の実装がその規則に従っているかは、次の差分比較とテストで確かめます。

## 証明と実装をつなぐ: 差分比較（diff.sh）

1. [Main.lean](Main.lean) が、証明したのと**同じ関数**を実行ファイル `kvescape escape|unescape` にする。
2. [diff.sh](diff.sh) が [samples/](samples/) の入力を `kvescape` と Go の CLI の両方に与え、結果を比べる。

比べたのはサンプル入力の範囲だけです。
それでも、例ベースのテストが見逃した `m14_escape_only_first_comma`（2 個目以降のカンマをエスケープしない）を検出しました。

```
FAIL escape "a,b,c,d": cli=[k=a\,b,c,d] lean=[k=a\,b\,c\,d]
```

## 実行

```bash
make lean   # lake build（ここで証明を検査する）→ diff.sh
```

ミュータントと比べるときは、`CLI` を差し替えます。

```bash
container run --rm -e CLI=/opt/mutants/m14_escape_only_first_comma kvjson-lean
```

## 証明の読み方（概略）

`unescape_escape` は、文字列（文字のリスト）の長さについての帰納法で示します。

- 空の文字列: 両辺とも `some []` なので自明。
- 先頭が `c` の文字列: `c` が 4 つの特殊文字のどれかで場合分けする。
  - 特殊文字なら、`escape` は `\` と 1 文字を出し、`unescape` はそれを `c` に戻す。残りは帰納法の仮定により元に戻る。
  - 特殊文字でなければ、`escape` は `c` をそのまま出し、`unescape` もそのまま通す。
